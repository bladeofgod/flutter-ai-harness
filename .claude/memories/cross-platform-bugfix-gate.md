# 单端复现问题的修复边界

共享 Dart 或 Bridge 代码只在某个平台失败、其他生产平台稳定时，先分类问题：

| 情况 | 修改策略 |
| --- | --- |
| 只在一个平台复现，且已证明根因属于该平台实现或 SDK | 用平台 Gate 限定修复或 workaround |
| 所有平台都会复现或共享逻辑本身错误 | 修公共路径，并验证所有平台 |
| 新增独立能力 | 增加新分支，不改变稳定路径 |

“只在一个平台复现”只是调查信号，不足以证明根因属于该平台。必须先定位共享逻辑、输入差异和平台实现边界，再决定是否增加 Gate。Gate 可以放在 Flutter 平台能力判断、各端 Bridge 实现或原生条件编译处。

不得用平台 Gate 掩盖真实公共缺陷，也不得为了一个 SDK 的特殊实现重写其他稳定平台的公共路径。任务卡或 Review 中必须记录分类依据和跨端验证证据。
