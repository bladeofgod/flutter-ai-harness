## 日志门面

- 决策状态：延后。
- 实现状态：未实现。
- 目标所有者：`app_core`。
- 首个消费者：至少两个生产消费者、统一错误采集或 App Operator 证据需求出现时实现。
- 采用模式：定义窄接口并通过构造函数注入，具体输出在组合根装配。
- 禁止耦合：不得预置业务标签、账号字段、真实数据、静态全局 Logger 或 Feature 专属上报协议。
- 启用验证：覆盖级别过滤、敏感信息脱敏、错误边界和多个消费者，并运行 `make evidence-lint`、`make analyze` 与 `make lint`。

## 运行环境

- 决策状态：延后。
- 实现状态：未实现。
- 目标所有者：`app_core` 定义契约，`apps/demo` 负责装配。
- 首个消费者：出现真实环境、Endpoint 配置或构建时行为差异时实现。
- 采用模式：使用不可变、类型明确的 Value Object，由组合根显式构造并注入消费者。
- 禁止耦合：不得读取入库的 `.env`、携带密钥、混入产品实验或 Feature 开关，也不得让业务层直接读取进程环境。
- 启用验证：覆盖配置解析、缺失值和各环境确定性默认值，并校验敏感信息与本机路径不会入库。

## ServiceInitializer

- 决策状态：延后。
- 实现状态：未实现。
- 目标所有者：`apps/demo` 组合根。
- 首个消费者：已经存在多个确需按顺序执行启动初始化的全局 Service 时实现。
- 采用模式：显式、有序、可失败地编排已存在 Service。
- 禁止耦合：在 `AuthService`、`UserService` 等真实 Service 出现前不得创建空框架，不得通过扫描、反射或隐藏服务定位器发现依赖。
- 启用验证：覆盖初始化顺序、重复调用、部分失败、释放和启动失败呈现，并保持每个 Service 可独立测试。
